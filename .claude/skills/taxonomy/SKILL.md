# סיווג מוצרים

ארבע שכבות, וכל אחת שוברת את הבאות אחריה אם היא שגויה:

| שכבה | איפה | מה היא קובעת ללקוח |
|---|---|---|
| מחלקה | `src/catalog/categorize.js` (`CATEGORY_RULES`, 15 מחלקות) | באיזה עמוד המוצר מופיע |
| מושג | `config/concepts/*.json` | מה המוצר *הוא*: מה נחשב אותו דבר בשתי רשתות |
| משפחה | תחילית מזהה-המושג עד המקף + `config/concepts/families.json` | שבבי תת-הקטגוריה בתוך המחלקה |
| תחליפים | `config/substitutes/rules.json` | מה מוצע כחלופה זולה יותר |

המנוע ב-`src/catalog/concepts.js`: השם עובר `normalizeText` (אותיות סופיות ך ם ן ף ץ הופכות לרגילות, גרש וגרשיים נמחקים), ואז `all` / `any` / `none`, ואז שומר ה-`kind` מול אוצר מילות-הסוג. שני מושגים שתופסים את אותו שם = קונפליקט, והבנייה מפילה את שניהם.

## החוק הראשון: סבב הוא על משפחה, אף פעם לא על מוצר

ב-24.9 נאור הצביע על הפטריות. `mushroom-button` תפס בלינצ'ס עם פטריות וגבינת ברי עם פטריות, ובו-זמנית לשיטאקי, שימאג'י, שינוקי ומיקס אקזוטי לא היה מושג בכלל - 67 מתוך 125 תוצאות הפטריות ישבו מחוץ למשפחת הפטריות. רחב מדי וצר מדי באותו רגע, כי כל סבב קודם נכתב על המוצר שמישהו הבחין בו.

לכן: פותחים סבב מתוך אשכול, ממפים את **כל** הזנים שהרשתות מפרסמות, וכותבים את כולם יחד. מי שכותב מושג לזן אחד ומשאיר את אחיו - מייצר בדיוק את אותה תקלה במקום אחר.

## מתי בכלל כותבים מושג

לא לכל מוצר מגיע מושג. החלטת נאור (24.9): **אשכול זכאי למושג כשיש בו לפחות 3 מוצרים שונים או שהוא מגיע ל-2 רשתות**. מושג קיים כדי ששתי שורות של אותו דבר יושוו זו לזו ויוצעו כתחליף - למוצר יחיד ומיוחד אין למי להשוות אותו. `concept-clusters.mjs` סופר את האשכולות הבודדים ומשאיר אותם בכוונה; הם לא תור עבודה.

המדד אינו "אחוז המוצרים עם מושג" אלא "כמה אשכולות גדולים עוד פתוחים".

## הנוהל

**0. מאיפה מתחילים - מהנתון, לא ממה שמישהו הבחין בו**

```bash
node scripts/concept-clusters.mjs --department "בשר ועוף" --top 20
```

**1. ממפים את המשפחה המלאה**

```bash
node scripts/concept-clusters.mjs --department "בשר ועוף" --expand פילה
```

ראש אשכול הוא משפחה, לא מושג: `פילה` הוא 155 מוצרים ו-28 זנים. לפני כתיבה, לאמת כל זן מול השמות הגולמיים - `grep` ב-`data/prices/<chain>/catalog.full.json` - כי שם הזן מתפצל לכתיבים (`סלמון` ו-`סלומון`, `פורטבלה` ו-`פורטובלו`), ומילה שנראית כמו זן לפעמים אינה כזו (`פילה פרימיום`, `פילה דג` שהוא בעצם אמנון).

**2. צילום לפני**

```bash
[ -e data/prices ] || ln -s /Users/naorlugassi/Projects/Cart/data/prices data/prices
node scripts/concept-round.mjs --snapshot /tmp/before.json --raw
```

הבדיקה `[ -e ]` אינה קישוט: `ln -s <יעד> data/prices` כשהנתיב כבר קיים כתיקייה יוצר קישור **בתוכה**, `data/prices/prices`, שמצביע על ההורה שלו. זה קישור מעגלי, והוא מפיל כל סריקת תיקיות שעוקבת אחרי קישורים - טעינת DuckDB או גיבוי. קרה ב-24.9 ונמצא על ידי סשן אחר. למחוק את הקישור לפני הקומיט, ולוודא ש-`git status` ריק תחת `data/`.

**3. כותבים את הכללים** ב-`config/concepts/<קובץ>.json`. מבנה מושג:

```json
{ "id": "mushroom-shiitake", "name": "פטריות שיטאקי", "category": "ירקות ופירות",
  "sizeUnit": null, "synonyms": ["שיטאקי"], "kind": "fresh",
  "match": { "all": ["פטרי"], "any": ["שיטאקי", "שיטאקה"], "none": ["מרק", "אבקת"] } }
```

המזהה הוא `<משפחה>-<זן>`: התחילית עד המקף הראשון היא מה שמחבר את האחים למשפחה. `kind` אומר מה המושג *הוא*, לא באיזה מצב המוצר - כששני המצבים הם אותו מושג, `any` (שניצל עוף טרי ושניצל עוף קפוא הם אותו דבר).

**4. צילום אחרי, ולקרוא את העמודה LOST**

```bash
node scripts/concept-round.mjs --snapshot /tmp/after.json --raw
node scripts/concept-round.mjs --diff /tmp/before.json /tmp/after.json
```

ואז המספר שעליו הסבב נשפט, ברמת המוצר ולא ברמת השם:

```bash
node scripts/concept-round.mjs --verdict /Users/naorlugassi/Projects/Cart
```

שתי ספרות, תמיד יחד: כמה מוצרים קיבלו מושג, וכמה מוצרים נכנסו לקונפליקט ולכן נפלו. שם בקונפליקט הוא שקט ולא קטלני, כי הבנייה מצביעה על כל השמות של הברקוד - אבל מוצר שכל שמותיו בקונפליקט יוצא משכבת המושגים לגמרי.

כל שורת `LOST` היא או מטרת הסבב או רגרסיה, ובהודעת הקומיט צריך להיות כתוב איזו מהשתיים. מושג שכיווצנו בכוונה - לומר כמה ולמה. מושג שכיווץ ולא התכוונו - זה באג, גם אם מה שרצינו עבד.

**5. מחלקה.** אם מוצר של המשפחה יושב במחלקה הלא נכונה, לתקן ב-`CATEGORY_RULES` באותו סבב. הבלינצ'ס לא היה רק מושג שגוי - הוא ישב ב"ירקות ופירות", ולכן שומר המזון/לא-מזון לא יכול היה לתפוס אותו. לבדוק לשני הכיוונים: `node scripts/dead-keywords.mjs` למילה שנכתבה בצורה שהרשתות לא משתמשות בה.

**6. משפחה.** אחים חולקים תחילית ולכן נכנסים למשפחה לבד; שם עברי ב-`families.json` רק אם ברירת המחדל (שם האח הקצר ביותר) אינה מה שהלקוח צריך לראות. תחילית שרשומה שם בלי שני אחים - הבדיקה נופלת.

**7. ארבע הביקורות, כולן**

```bash
node scripts/concept-health.mjs            # מושג שבולע מוצרים ממחלקה אחרת
node scripts/concept-dead-rules.mjs        # כלל שלא תופס כלום - נראה בדיוק כמו כלל שעובד
node scripts/concepts-report.mjs --category "..."   # קונפליקטים וכיסוי
node scripts/substitute-audit.mjs          # ואחרי שינוי שם מזהה: grep -n '<מזהה-ישן>' config/substitutes/rules.json
node scripts/concept-why.mjs <ברקוד>       # למה דווקא הברקוד הזה קיבל את זה
```

**8. בדיקות.** לכל מושג חדש שתי בדיקות ב-`test/conceptRules.test.js`: שם שהוא חייב לתפוס, ושם קרוב שהוא חייב לדחות - הדחייה היא זו שמחזיקה. להריץ `npm test` ולוודא את המחרוזת `ℹ fail 0` מילולית; `✖` בפלט של node חמק ממני פעם אחת ודחפתי בדיקה אדומה.

**9. קומיט.** קוד וקונפיג בלבד. `git checkout -- data/` לפני הקומיט - רק מרלוג מפרסם נתונים. אחרי `rebase`, **למדוד שוב**: שני סבבים שכל אחד תקין לבד יכולים להישבר יחד, כי שניהם נוגעים באותם שמות.

## גבולות

- לעולם לא לערוך את הרשימה המבוקרת (`config/categories/labels.json`, `concept-reviewed.json`) כדי שכלל יעבור. מתקנים את הכלל.
- `data/` נבנה ונדחף רק במרלוג. סשן מקומי שבנה מקומית - `git checkout -- data/`.
- עץ העבודה משותף לכמה סשנים: לא לעשות `checkout` מעל קבצים של אחר, ולא לגעת בקובץ מושגים שסבב אחר פתח עליו.
- פריסה ומיזוג ל-main הן החלטות של נאור.
