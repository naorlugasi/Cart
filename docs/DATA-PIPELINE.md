# שירות הורדת המחירונים - אפיון (טיוטה 9.9.2026)

חלק 1 של [PRODUCT.md](PRODUCT.md). המטרה: כל יום, כל המחירונים של כל הרשתות וכל הסניפים, במסד נתונים שמשרת את שני השירותים (אונליין ובסניף).

## 1. מה מורידים

לפי חוק שקיפות המחירים כל קמעונאי מזון גדול מפרסם, לכל סניף, קבצים בפורמט אחיד (XML, בדרך כלל gzip):

| קובץ | תוכן | תדירות | גודל טיפוסי (gz) |
|---|---|---|---|
| `PriceFull<chain>-<store>-<ts>` | כל המוצרים והמחירים בסניף | יומי (בוקר) | 0.5-5MB, 5k-30k שורות |
| `Price...` | שינויי מחיר מאז הקובץ המלא | כל שעה בערך | קטן |
| `PromoFull...` / `Promo...` | מבצעים (חוקי תמחור, תוקף, מועדון) | יומי / שעתי | 0.1-2MB |
| `Stores...` | רשימת הסניפים: מזהה, שם, כתובת, עיר, סוג | יומי / שבועי | קטן |

**בגרסה הראשונה מורידים רק Full (מחירים + מבצעים) פעם ביום, ו-Stores פעם בשבוע.** קובצי delta נשארים לשלב ב' (מחירים תוך-יומיים כמעט לא משנים לסל שבועי).

## 2. היקפים
- שורות מחיר ביום: ~2,500 סניפים × ~15,000 מוצרים ≈ **40 מיליון**.
- הורדה ביום: 2,500 × ~2MB ≈ **5GB gz** (טווח 3-8GB). ~150GB לחודש.
- מה באמת משתנה: 1-5% מהמחירים ביום. לכן מסד הנתונים שומר **מצב נוכחי** (40M שורות, ~3-5GB עם אינדקס) ו**שינויים** בלבד (1-2M שורות ביום).
- הרבה סניפים באותה רשת מפרסמים מחירון זהה (רמי לוי אחיד, שופרסל לפי אזורים). מזהים לפי hash של התוכן ולא מעבדים פעמיים.

## 3. איך זה עובד (צינור יומי)

```
06:00  fetch   רשימת קבצי היום מכל פורטל → הורדה מקבילית (8 במקביל, retry ×3) → ארכיון (R2/S3: raw/<chain>/<date>/<file>)
06:40  parse   XML (UTF-8/UTF-16, gzip/zip) → שורות אחידות → hash לכל קובץ; קובץ זהה לאתמול = דילוג
07:10  diff    לכל סניף: השוואה למצב הנוכחי → שורות חדשות/משתנות/נעלמות
07:20  load    upsert ל-prices_current, append ל-prices_history, promos, stores (+גיאוקידינג לסניף חדש)
07:40  build   products/concepts (מוצר חדש → תור העשרה), קטלוגי האונליין (הקיים היום), סטטיסטיקות
07:50  check   בדיקות שפיות לכל רשת: מספר סניפים, מספר מוצרים, מחיר חציוני, סטייה >30% = התראה; רשת שלא פרסמה = התראה
12:00  retry   ריצה שנייה רק לרשתות שנכשלו/לא פרסמו בבוקר
```

- **אידמפוטנטי**: כל ריצה מזוהה ב-(chain, date); הרצה חוזרת לא מכפילה נתונים. אפשר להריץ "backfill" לתאריך מהארכיון.
- **מניפסט** לכל ריצה: אילו קבצים נמצאו, הורדו, נותחו, כמה שורות, זמן, שגיאות → טבלה `pipeline_runs` שמוצגת באתר הניהול.
- **דרייבר לכל סוג פורטל** (Cerberus, Shufersal-Azure, Electra, Laib/Matrix, HTML-listing, Static-listing) + קובץ הגדרות לכל רשת: `{ chainId, driver, baseUrl, username, storeFilter, encoding, schedule }`. רשת חדשה = שורה בקובץ, לא קוד.
- **דפדפן אמיתי** (Playwright) רק לדרייברים שדורשים (Laib/Matrix); השאר HTTP רגיל, זול יותר.
- קוד קיים לשימוש חוזר: `scripts/fetch-prices.mjs` (דרייברים ל-4 פורטלים), `src/catalog/priceXml.js` (פרסר), `scripts/build-products.mjs`.

## 4. איפה זה רץ (ההחלטה הכי חשובה)
חלק מהפורטלים חוסמים כתובות של ענן ציבורי (AWS/GCP/Azure). צריך לאמת ביום הראשון מול כל פורטל. שלוש אפשרויות:

| אפשרות | עלות | יתרון | חיסרון |
|---|---|---|---|
| **A. VPS ישראלי** (Kamatera/Cloudwm, 2-4 vCPU, 8GB, 100GB) | ~$20-40 לחודש | IP ישראלי, זמין 24/7, קרוב לפורטלים | לבדוק חסימות |
| B. Hetzner (גרמניה), 4 vCPU 8GB | ~€7-8 לחודש | זול מאוד, חזק | IP ענן אירופאי, סיכוי גבוה יותר לחסימה |
| C. מיני-PC בבית (N100, 16GB) + Tailscale | ~₪700 חד-פעמי, ~₪15 חשמל | IP ביתי, אף אחד לא חוסם | תלוי בחשמל/אינטרנט בבית, תחזוקה |

המלצה: **A**, ואם פורטל מסוים חוסם גם אותו, לרוץ עבורו מ-C או דרך ISP proxy קטן (רק ל-fetch, כמה GB בחודש). ה-DB והאתר לא חייבים להיות באותו מקום.

## 5. אחסון ו-DB
- **מסד נתונים**: Postgres. `prices_current(store_id, gtin, price, unit_price, promo_ref, in_stock, updated_at)` עם PK (store_id, gtin) ואינדקס (gtin) לתמחור סל מול הרבה סניפים; `prices_history` מחולק לפי חודש; `stores`, `products`, `promos`, `pipeline_runs`. ~5-8GB בשנה הראשונה.
  - מנוהל: Supabase Pro ($25 + אחסון) או Neon (~$20-40). או Postgres על אותו VPS (חינם, אבל גיבויים עלינו).
- **ארכיון קבצים גולמיים**: Cloudflare R2, $0.015/GB לחודש, בלי עלות יציאה. 14 יום = ~70GB ≈ $1; שנה = ~1.8TB ≈ $27. המלצה: 30 יום מלא + Stores/PromoFull לשנה.
- **שאילתת הליבה** (סל של 50 פריטים × 40 סניפים ברדיוס): קריאה אחת `WHERE gtin = ANY($1) AND store_id = ANY($2)` על האינדקס, < 100ms.

## 8. סיכונים
- חסימות IP (סעיף 4). מתגלה ביום 1.
- פורטל שמשנה מבנה (קרה עם laib) - הדרייבר נכשל, ההתראה עולה, מתקנים. לכן דרייבר לכל פורטל ולא קוד אחד.
- איכות: שמות קצוצים, ברקודים פנימיים (לא GTIN) לשקילים ולמותג פרטי, סניפים בלי כתובת. מטופל בשכבת ההעשרה ובתור התיקונים.
- חוקי: הנתונים ציבוריים לפי חוק; מציגים מקור ותאריך עדכון ליד כל מחיר.

## 9. החלטות פתוחות

2. Postgres מנוהל או על ה-VPS.

4. האם להוריד גם קובצי delta תוך-יומיים בגרסה הראשונה (מוצע: לא).
